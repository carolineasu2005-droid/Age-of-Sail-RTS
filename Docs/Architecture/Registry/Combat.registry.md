# Combat Gameplay Registry

**Registry status:** Foundation Phase 7E Implemented / Pending Developer Unity Gate Validation

This registry freezes the approved ownership and dependency boundaries for the
Combat Gameplay Foundation. Phase 1A activates the authoritative per-ship
`ShipCombatState` owner and its controlled mode/target state. Phase 1B adds
independent Port/Starboard Ready-to-Reloading-to-Ready state, owner-only reload
progression, shared temporary reload configuration, and Gelderland integration.
Phase 2A added the geometric Fire Eligibility calculation and temporary
broadside-arc/range configuration. Phase 2B completes the read-only Foundation
eligibility decision by combining structural/caller-provided target legality,
the applicable authoritative broadside reload state, a narrow Combat Geometry
obstruction query, and an explicit lifecycle result boundary. Phase 6
implements physical Foundation firing and geometric/semantic outcomes. Phase
7A activates authoritative ship-wide Integrity and lifecycle state. Phase 7B
connects an already-resolved valid Round Shot Hull Hit to temporary Foundation
Damage and controlled Integrity loss. Phase 7C activates lifecycle permissions:
only an Operational shooter may fire; Operational and CombatDisabled targets
remain legal, while Sinking targets are illegal for new targeted solutions and
Auto Target selection. Phase 7D adds a simple one-way presentation consumer
that lowers only `ShipArtDefinition.VisualRoot` after Sinking. Phase 7E verifies
the complete physical-hit-to-Damage-to-lifecycle-to-presentation chain,
preserves one authoritative semantic hit region for both Damage and VFX, and
exposes a read-only latest-terminal-resolution diagnostic snapshot. Automatic
firing scheduling remains `Planned`.

Phase 2C adds an Editor-only `ShipTestPanel` consumer for explicit shooter and
target inspection. The immutable result now preserves the exact obstruction
origin/destination used by its authoritative query so debug presentation does
not reconstruct that spatial fact. The Scene visualization adds no runtime
state, query owner, or gameplay decision.

Phase 3A activates atomic Manual Target / Auto Fire arbitration on the existing
`ShipCombatState` owner. A valid Manual Target assignment disables Auto Fire;
explicitly enabling Auto Fire clears Manual Target. Assignment validates only
the minimum Combat Root identity and remains independent of current Fire
Eligibility, Movement, Blind Fire, target discovery, and firing execution.

Phase 3B activates stateless Auto Target scoring for candidates already
accepted by Fire Eligibility. The explainable score is exactly normalized
Target Exposure multiplied by a temporary linear Range Quality. Scoring reads
registered Combat Art and Movement pose contracts without discovering,
selecting, retaining, steering toward, or firing at a target.

Phase 3C activates stateless Auto Target selection over an explicit set of
immutable candidate values. Phase 3E corrects the result to preserve the
existing broadside boundary: one pass keeps at most one best legal Port target
and at most one best legal Starboard target. The caller-supplied candidate list
has no artificial gameplay count limit. No authoritative ship enumeration or
faction/allegiance Source of Truth exists, so each caller currently supplies
only a target Ship Root and its relationship-allowance fact. The selector gates
on Auto Fire with no Manual Target, evaluates authoritative Fire Eligibility
before scoring, and routes each accepted candidate only by that result's
`CombatSide`. It discovers no objects, retains no CurrentAutoTarget, steers
nothing, and fires nothing.

Phase 3D connects single-selection player right-click input to the existing
Manual Target command. A clicked Combat hierarchy child resolves upward to the
authoritative Root carrying the registered `ShipCombatState`; the controllable
shooter still comes from the existing `ShipDestinationController` selection.
Accepted assignment uses the Phase 3A atomic
command, so Auto Fire turns off without issuing any Movement command. Invalid,
non-Combat, self, or multi-selection targeting attempts do not consume the
click and preserve the existing destination/formation path. Editor-only debug
presentation now consumes explicit Phase 3C/3E candidates and results without
creating a production discovery owner.

Phase 3F completes the Editor-only verification surface for Phase 3. The Ship
Test Panel owns a dynamic add/remove/reorder list of explicit debug candidates,
passes the complete list to the existing Phase 3E selector, and presents
independent Port and Starboard result diagnostics and Scene lines. It does not
add candidate discovery, duplicate eligibility/scoring rules, persist targets
into runtime Combat state, or change any gameplay contract. Phase 3 remains
pending the developer-run Manual Unity Gate.

Phase 4A activates a targetless Blind Fire aim and eligibility query. Explicit
World-point and World-direction inputs resolve through the same pure broadside
classification used by target-aware Fire Eligibility. Point mode copies the
finite point, measures direct Root-to-point World distance, and applies the
inclusive Maximum Range; direction mode copies a normalized horizontal World
direction and deliberately has no point, distance, or range verdict. Both read
only the applicable broadside readiness and current authoritative shooter
lifecycle permission. They acquire no target, query no Exposure or obstruction, commit no
reload, and write no Movement or Combat state.

Phase 4B introduced the authoritative per-action Blind Fire command. Phase 4B.1
assigns that action to the dedicated stateless `ShipBlindFireCommand` service,
leaving `ShipFireEligibility` an authoritative read-only evaluator. The command
accepts an immutable Phase 4A aim, requests fresh eligibility from
`ShipFireEligibility` using current Root pose and reload state, requires exactly
one legal side, and delegates the one reload transition to
the common physical broadside executor. Only a successful common execution
disables Auto Fire; it leaves Auto Fire off and preserves any Manual Target.
Rejection changes neither broadside timer, Auto Fire, Manual Target, nor
Movement. Phase 6E supersedes the former intent-only execution: a legal finite
point now produces Shot Samples and Projectiles through the common executor.
Direction-only eligibility remains queryable but physical execution rejects it
with `FiniteAimPointRequired` rather than inventing a range.

Phase 4C adds a Foundation-safe player-command adapter without assigning a new
keyboard binding. The existing Editor Ship Test Panel can arm Blind Fire for
one next valid right-click World/sea point. That consumed attempt delegates to
the Phase 4A query and Phase 4B action, whether accepted or rejected, and never
falls through to Manual Target, Destination, or formation placement. Arming is
transient input-layer state only, clears on selection change/cancel/attempt,
and is not Combat target ownership. Editor diagnostics display the immutable
adapter/Combat results and are not gameplay authority. Phase 4 is closed and
passed.

Phase 5A formalizes the existing Phase 3B Auto Target score without changing its
default behavior. `AutoTargetScoringProfile` is the temporary, playtest-bound
policy asset referenced by one Root-level
`ShipAutoTargetScoringConfiguration`. The immutable score now reports distinct
normalized Exposure (E), Range Quality (R), and Visibility/Observation Quality
(V) factors. Foundation V is intentionally fixed to exactly `1.0`, so the
effective score remains `E * R`. No smoke, visibility query, Accuracy,
Dispersion, Shot Sample, or Projectile implementation is activated.

Phase 5B closes the implementation-side integration gate around that contract.
The existing Editor-only Ship Test Panel displays the selected Port and
Starboard target plus authoritative E, R, V, and FinalScore values without
recalculating them. Regression coverage proves same-range Exposure preference,
near/far Range Quality, Maximum Range exclusion, neutral V, and score-driven
competition independently on both sides. Phase 5 is Closed / Pass.

Phase 6A activates the target-independent geometric handoff used by future
Shot Sampling. Targeted and point-based Blind Fire inputs become one immutable
`FireAimBasis`; the targeted path takes only the aim-plane center from Target
Exposure and retains the already-authoritative Fire Eligibility distance and
side. Direction-only Blind Fire remains a valid Phase 4 query/action input but
is explicitly rejected for physical basis construction with
`FiniteAimPointRequired`; no hidden finite target is invented. Dispersion then
uses only the basis plus a temporary Combat-owned angular profile to build the
frozen World-space plane, rectangle, and inscribed ellipse. Direct `sqrt(u)`
ellipse mapping and an isolated xorshift32 generator provide deterministic
sampling infrastructure without global random state.

Phase 6B activates pure broadside Shot Sampling. One accepted `FireAimBasis`
selects exactly one authoritative Port or Starboard muzzle collection, preserves
its Combat Art Bow-to-Stern order, validates the complete collection before
output, and creates exactly one immutable `ShotSample` per participating muzzle.
Each sample copies its World origin, deterministic ellipse point, broadside seed,
sequence index, Round Shot identity, launch velocity, gravity, nominal flight
time, flat WaterlineReference World Y, and maximum lifetime. A temporary,
playtest-bound Projectile Flight profile supplies launch-state tuning only. The
sampler retains no muzzle Transform, mutates no Combat/Movement/Art state, and
does not commit reload, spawn a Projectile, decide Hit/Miss, emit VFX, or apply
damage. Projectile simulation and every downstream resolution contract remain
`Planned`.

Phase 6C activates visible Foundation Round Shot Projectile simulation from one
immutable `ShotSample`. `CombatProjectile` evaluates the frozen analytic
trajectory directly, moves only its own transient GameObject, sweeps each
World-space segment against layer 8 Combat Geometry Triggers, excludes every
source-ship hierarchy hit, and independently calculates flat-water crossings
from the sample's copied water level. The earliest normalized contact wins;
Combat Geometry wins an epsilon tie with water. One immutable neutral terminal
contact is produced for Combat Geometry, water, or maximum-lifetime fallback,
then simulation stops and the placeholder is destroyed. The projectile retains
no target, uses no Rigidbody or gameplay Collider, performs no semantic
Bow/Midship/Stern resolution, and writes no reload, target mode, Integrity,
Damage, VFX, or Movement state.

Phase 6D activates the stateless semantic handoff downstream of that neutral
result. A Combat Geometry contact becomes a Hit only when its exact Collider
resolves through `CombatHitRegion.Owner` and the owning
`ShipCombatGeometry.TryResolveRegion` registration; the immutable context then
records target Root, descriptive Bow/Midship/Stern region, World point/normal,
incoming velocity/direction, source Shot Sample, and Round Shot identity. A
water contact becomes a targetless geometric Water Miss, while expiry remains
an explicit non-hit diagnostic. Only these resolved outcomes may be adapted to
the existing Combat Art hull/water VFX events. The receiver remains downstream
and cannot choose the result. Muzzle adaptation from a Shot Sample is available
for a later authoritative launch owner but is not emitted by Phase 6D. Damage,
Integrity, lifecycle changes, and Combat Resolution beyond this Foundation
classification remain `Planned`.

Phase 6E activates one authoritative physical broadside coordination path.
`ShipBroadsideFireExecutor` validates the finite aim and all sampling/spawn
dependencies, constructs the complete deterministic Shot Sample collection,
validates the Projectile prefab, calls
`ShipCombatState.TryCommitBroadsideFire` exactly once, then creates exactly one
Projectile and one optional muzzle presentation event per sample. Its immutable
result records the side, explicit seed, basis, read-only samples, and spawn
count. `ShipTargetedFireCommand` performs fresh target-aware Fire Eligibility
and Exposure-centered basis construction before delegation. Point-based
`ShipBlindFireCommand` performs fresh targetless eligibility and delegates to
the same executor; only common-execution success disables Auto Fire, while
Manual Target and Movement remain unchanged. Per-side runtime seed streams are
isolated and all sampling remains independent of `UnityEngine.Random`.
Projectile terminal events flow through the Phase 6D outcome resolver and VFX
bridge without Damage or Integrity mutation. The implementation is not marked
Closed / Pass until the developer-run Unity suites and Manual Phase 6 Gate pass.

Phase 7A activates one `ShipIntegrity` owner on the formal Combat Root. It
snapshots a temporary `ShipIntegrityProfile` during initialization, starts at
Maximum Integrity in `Operational`, clamps controlled Integrity loss to zero,
and deterministically evaluates inclusive normalized thresholds for
`CombatDisabled` and `Sinking`. `Sinking` always implies combat-disabled
semantics, while `CombatDisabled` does not imply `Sinking`; one large loss may
transition directly from `Operational` to `Sinking`. Bow/Midship/Stern remain
descriptive hit metadata and never become separate durability pools. Phase 7A
does not connect Projectile/Hit outcomes to this owner.

Phase 7B activates the stateless `CombatDamageResolver` downstream of the
existing immutable `FoundationShotOutcome`. Only a valid Round Shot `HullHit`
with its registered `CombatHitContext` may use the temporary
`CombatDamageProfile` formula `BaseDamage * RegionMultiplier` and request
controlled loss through `ShipIntegrity`. Bow, Midship, and Stern multipliers
all default to `1.0` and remain descriptive modifiers over the same ship-wide
pool. `WaterMiss`, `ExpiredNonHit`, and invalid/unresolved outcomes cause no
Integrity mutation. Projectile, semantic Hit Query, outcome values, and VFX
remain non-owning upstream/downstream boundaries.

Phase 7C connects the authoritative `ShipIntegrity.LifecycleState` to the
existing target-aware and targetless Fire Eligibility conjunctions. Shooter
permission is true only for `Operational`. Target lifecycle legality accepts
`Operational` and `CombatDisabled`, rejects `Sinking`, and remains independent
from caller-provided relationship legality. Auto Target filters that verdict
before scoring; lifecycle adds no E/R/V factor or preference. A retained Manual
Target may become ineligible without being cleared. Targeted and Blind Fire
commands perform fresh eligibility and reject before Shot Sampling, reload
commit, or Projectile creation. The common broadside executor stays
target-independent, and lifecycle integration writes no Movement, component
enabled state, GameObject active state, or Root pose.

Phase 7D activates `ShipSinkingPresentation` as a presentation-only consumer
of the authoritative lifecycle. On its first observed `Sinking` state it
snapshots the current `VisualRoot` local pose and temporary presentation values,
then applies a clamped linear local-Y descent and configured signed local-forward
roll exactly once. Operational and CombatDisabled do nothing. Completion leaves
the visual at its final pose without moving/destroying the authoritative Root,
changing lifecycle/Integrity, issuing Movement commands, or moving the sibling
Combat Geometry hierarchy. Presentation never decides gameplay state.

Phase 7E freezes the integrated handoff as Projectile terminal contact to
`FoundationShotOutcome`, `CombatDamageResolver`, `ShipIntegrity`, and lifecycle
permission/presentation, with the same immutable outcome independently
forwarded to VFX. Every spawned Projectile subscription
has a private once-only terminal-consumption gate. The executor retains only a
latest read-only diagnostic snapshot; it does not become Damage, Integrity,
lifecycle, target, or presentation authority. The Editor-only Ship Test Panel
reads authoritative owner/result values and performs no gameplay calculation.

Combat depends on the Movement authority boundary rather than replacing it:

- `MOV-REF-001` is the authoritative Ship Root.
- `MOV-STA-001` is authoritative world position.
- `MOV-STA-002` is authoritative physical Heading / `transform.forward`.
- Combat is a read-only consumer of those contracts. The Phase 1B state owner
  has no Movement reference and performs no Movement read or write. The Phase
  2B evaluator reads Root position/orientation, authoritative Combat reload
  state, and registered Combat Art spatial inputs; it never writes pose,
  Movement state, reload state, or Combat Art data. The Phase 3B scorer reads
  only the shooter Root position as its Exposure observer, plus the Root-level
  Phase 5A scoring profile reference, and likewise writes no upstream state.
  The Phase 3C selector composes those read-only queries and
  likewise creates only a transient result; it performs no pose, Movement,
  Combat state, reload, or Combat Art write. The Phase 4A Blind Fire query reads
  only Root position/orientation and applicable broadside readiness; an illegal
  direction is rejected and never corrected by steering. The Phase 4B.1
  `ShipBlindFireCommand` repeats that query immediately before commit and never
  writes Root pose or any Movement-owned state. The Phase 4C adapter only selects this command
  route; an armed attempt never dispatches a Movement or formation command.
  Phase 6A basis construction reads current Root position only to convert an
  accepted finite aim into immutable geometry. Phase 6B copies current
  side-specific muzzle World positions into immutable values. Dispersion and
  Shot Sampling perform no Root-pose or Movement-state write. Phase 6E targeted
  and point Blind Fire coordinate only Combat state, sample values, transient
  Projectile instances, and presentation output; neither command nor the common
  executor steers, assigns Destination, changes Formation, or writes Root pose.
  Phase 7B/7E Damage consumes only immutable outcome context and scalar profile
  values and likewise performs no Movement read or write. Phase 7D/7E reads the
  lifecycle state and writes only the registered `VisualRoot` local pose; Ship
  Root position, Heading, scale, and every Movement-owned value remain untouched.
- Combat Art spatial inputs are defined separately in `CombatArt.registry.md`.

## Frozen dependency direction

The allowed dependency direction is one-way:

```text
Combat Art Layer (Active read-only spatial contracts)
    |
    v
Combat Foundation Layer (Active Phase 1 state/reload, Phase 2 target-aware eligibility,
                         Phase 3/5 target scoring and per-side selection,
                         Phase 4 targetless Blind Fire query/action/input adapter,
                         Phase 6A aim-basis/dispersion geometry,
                         Phase 6B immutable broadside Shot Sampling,
                         Phase 6C analytic Projectile/neutral contact,
                         Phase 6D semantic outcome, Phase 6E common fire execution,
                         and Phase 7C lifecycle permission consumption)
    |
    v
Combat Resolution Layer (Active Foundation semantic classification;
                         Active Phase 7B Round Shot Damage -> Integrity;
                         Active Phase 7A Integrity/lifecycle Source of Truth)
    |
    v
Presentation Layer (Active Phase 7D/7E VisualRoot-only sinking presentation;
                    Active Combat Art/VFX receiver contracts;
                    Active common gameplay VFX emitter)
```

Movement remains an independent authority beside the Art Layer. Combat may read
the authoritative Root pose (`MOV-REF-001`, `MOV-STA-001`, `MOV-STA-002`) and,
when an approved fire solution needs it, composed motion (`MOV-STA-011` through
`MOV-STA-015`). These reads do not grant Combat write ownership.

outcomes, target geometry sourced from render data, Dispersion derived from or
stored in Exposure/Combat Geometry, retained writable muzzle Transforms in Shot
Samples, and any Combat or Combat AI write to the Movement Root pose.

**Active Phase 6A regression evidence:** changing the real registered
`DispersionProfile` horizontal half-angle, vertical half-angle, and Foundation
spread scale leaves E, R, neutral V=`1.0`, and
`AutoTargetScoreResult.FinalScore` unchanged. `ShipAutoTargetScorer` and
`ShipAutoTargetSelector` contain no Dispersion dependency.

The following implementation details remain intentionally open: automatic Auto
Fire scheduling, final Damage balance/advanced modifiers, future non-neutral visibility sourcing and
scoring policy, production receiver routing, visual rolling-fire timing, and
all playtest-bound values. Changing any frozen ownership or
dependency direction requires a Registry update before or with implementation.

contract or API in this skeleton:

- Crew complex interactions
- Rigging damage
- Fire/Flooding
- complex criticals
- per-gun independent arc
- per-gun independent reload
- half broadside
- boarding
- commander duel
- advanced combat AI
- full Combat HUD

Adding any deferred system requires an explicit architecture/Registry change;
its appearance in this list does not reserve an API or implementation design.
