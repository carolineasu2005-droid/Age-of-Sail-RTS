# Combat Art / Ship Spatial Integration Registry

**Registry status:** Foundation / Partially Active

This Registry records approved Combat Art and ship-spatial boundaries. The
minimal `ShipArtDefinition` component, its explicit reference accessors,
Length/Beam queries, the dedicated Phase 1 placeholder-prefab integration, and
the Phase 2A `ShipMuzzleSockets` collection contract, the Phase 2B Gelderland
muzzle hierarchy and passive Scene-view gizmos, the Phase 3A Combat Geometry
semantic/query contract, and the Phase 3B Gelderland query-hull integration
are `Active`. Formal-art calibration, exposure, VFX hooks, and the validator
remain `Planned` until implementation evidence is added.

Governing dependencies:

- `PRJ-CONV-001` defines 1 Unity Unit = 1 meter.
- `PRJ-CONV-002` defines +Z Bow, +X Starboard, and +Y Up.
- `PRJ-CONV-003` / `MOV-REF-001` define the Formal Ship Root.
- `MOV-STA-001` and `MOV-STA-002` retain position and Heading authority.
- `PRJ-CONV-004` keeps `VisualRoot` presentation-only.
- `PRJ-CONV-005` defines Combat Geometry layer index `8`, Trigger volumes, and
  explicit `QueryTriggerInteraction.Collide` query behavior.

Combat Art may read the Movement Root and build child-space references from it.
It must not write Movement Root position or Heading.
Movement remains the writer of authoritative Root movement state:
`ShipSailingSpeed` owns Root translation and `ShipTurning` owns Root Heading,
as registered by `MOV-STA-001` and `MOV-STA-002`.

placeholder:

```text
└── MainHull                 (logical grouping; no collider required)
    ├── Bow                  (actual query region)

```

`CombatGeometry` Unity Layer at index `8`. `MainHull` remains a collider-free
logical container. Current centers and sizes are provisional placeholder
calibration and are not formal Gelderland art data.
