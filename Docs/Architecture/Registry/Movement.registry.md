# Movement / Sailing Interface Registry

This file is the minimum Movement/Sailing registry needed for Combat Art and
Combat Gameplay integration. It records verified current contracts, not every
public member or runtime debug field. Registry governance is defined by
[`REGISTRY_RULES.md`](REGISTRY_RULES.md); project scale, axes, and Root identity
are defined by [`PROJECT_CONVENTIONS.md`](PROJECT_CONVENTIONS.md).

Unless a row says otherwise, state access is public read-only, reading it has
no side effects, Status is `Active`, and Replacement is N/A. “Planned Consumer”
names an intended future reader; it does not claim that Combat code exists.

## 9. Known ownership relationships

| Contract / flow | Source of Truth and write ownership | Verified dependency |
|---|---|---|
| Root translation (`MOV-STA-001`) | Root position is authoritative; `ShipSailingSpeed` is the runtime translation writer. | It integrates `MOV-STA-013` in `ShipSailingSpeed.Update`. |
| Root rotation / Heading (`MOV-STA-002`) | Root orientation is authoritative; `ShipTurning` is the runtime rotation writer. | `ShipHeadingController` requests rudder through `MOV-API-002`; it does not own world position or directly rotate the Root. |
| Formation geometry | Formation is a reader, not a Root pose writer. | `FormationGeometrySnapshot` reads `ShipDestinationController.transform.position` and `.forward`; formation control uses the same component Transform as ship entity geometry. |
| Sailing composition | `ShipSailingSpeed` owns cached wind-relative, target-speed, velocity, Course, and translation state. | `ShipLeeway` calculates the lateral component; `ShipSailingSpeed` owns the published copy and composed `ActualVelocity`. |
| Maneuver delegation | Planner owns selection/delegation; Heading/Tack/Wear own their individual lifecycles. | Execute APIs delegate to exactly one owner; planner polls owner activity. |
| Profile handoff | `ShipMovementProfile` is authored configuration Source of Truth; runtime components own applied copies. | `ShipMovementProfileController.ApplyProfile` copies values to speed, turning, and Tack during `Awake`. |
| Combat boundary | Movement retains all Root translation/Heading write ownership. | Combat is a Planned Consumer and may read registered Movement state; Combat must never gain implicit permission to write Movement Root position or heading. |
